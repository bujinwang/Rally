# Story 6.11: Wire Up Tournament Analytics (orphaned route + orphaned screen)

## Status: Implemented — verified (see `6.11.design.md` §7)

## Story

As a tournament organizer,
I want a tournament analytics view showing participation, bracket efficiency and ranking movement,
So that I can see how a tournament actually ran.

## Context Source

- Origin: found during Story 6.10 follow-up recon (see `.workbuddy-ai/memory/2026-09-16.md`).
- Enhancement Type: **defect remediation + wiring** (three orphaned pieces joined up).
- Existing System Impact: mounts an existing unmounted route, fixes its response contract and
  access model, adds one frontend API method, and registers an existing orphaned screen.

## Problem statement

The `AnalyticsData` "shape mismatch" flagged in `6.10.design.md` §3 is a **symptom of missing
wiring**, not a type error. Recon, all read from source:

| Piece | State |
|---|---|
| `frontend/Rally/src/components/TournamentAnalyticsScreen.tsx` | **orphaned** — zero references; not in `components/index.ts`, not in any navigator |
| `backend/src/routes/tournament-analytics.ts` (`GET /:id/analytics`) | **never imported, never mounted** |
| its service `TournamentAnalyticsService` | returns **exactly** the 8 fields `AnalyticsData` declares |
| what the screen actually calls | `/tournaments/:id/stats` — 6 fields, **2 of 8** overlap |

So the screen was written against an `/analytics` contract that was never connected, and the
endpoint that would satisfy it has been unreachable since it was written.

## Acceptance Criteria

**Backend**

1. `GET /api/v1/tournaments/:id/analytics` is **mounted** and reachable.
2. It responds with the codebase's standard envelope: success `{ success: true, data: {...} }`;
   failures `{ success: false, error: { code, message } }`. (The route currently returns a raw body
   and `{ error: '...' }` on failure — both inconsistent with every sibling route.)
3. **Access model**, consistent with the device-first app (Story 6.1's `optionalAuth`):
   - anonymous → may read a **PUBLIC** tournament's analytics;
   - anonymous → `404` for a PRIVATE one;
   - authenticated organizer → may read their own;
   - present-but-invalid token → `401 UNAUTHORIZED`.
4. The `'Unknown'` magic-string sentinel in the organizer clause is removed; the organizer
   predicate is included only when an authenticated user exists.

**Frontend**

5. `tournamentApi.getTournamentAnalytics(id)` returns the typed payload and attaches `x-device-id`
   (reusing `bracketRequest`, the established device-first path).
6. `AnalyticsData` matches the service's actual output — all 8 fields, verified field by field.
7. `TournamentAnalyticsScreen` consumes the typed payload: no `as any`, no envelope read, and no
   dependency on `/stats`.
8. The screen is **reachable**: registered in `TournamentsStackNavigator` with
   `{ tournamentId, tournamentName }` params, plus an entry point from `TournamentDetailScreen`.

**Quality**

9. Backend `tsc --noEmit` clean; backend suite green with counts recorded; new route tests added
   (mounted, envelope shape, and each access case in AC 3).
10. Frontend `npx tsc --noEmit` clean; frontend failure count not worse than the recorded baseline.
11. A **live probe** against a real server + real Postgres proves the route end-to-end (status,
    envelope, and the 8 field names) — route work is not proven by unit tests alone.
12. Clean-checkout verification (`git archive HEAD`) matches the working tree.

**Non-functional**

13. No change to `TournamentAnalyticsService`'s computation (it is correct and already tested by
    its own suite); this story is wiring, not maths.
14. The unmounted route file's unused imports are cleaned up if they are genuinely unused.

## Out of scope

- The second, *mounted* analytics endpoint `GET /analytics/tournament/:tournamentId`
  (`routes/analytics.ts:173`), which reads the 4-column `tournament_analytics` table. It is a
  different (coarser) data source and is left alone. Its divergence is noted, not merged.
- `tournamentApi`'s `TournamentStats` type drift (declares `totalGames`/`totalSets`/
  `currentRound`/`tournamentProgress` the backend never sends) — separate defect.
- Any redesign of the analytics UI.
