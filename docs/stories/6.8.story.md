# Story 6.8: Community and Social Engagement

## Status: Draft

## Story

As a community manager,
I want a feed, sharing, and satisfaction signals,
So that I can grow and retain the badminton community.

## Context Source

- Source Document: docs/epics/epic-6.md (Story 6.8, Workstream WS8)
- Enhancement Type: Brownfield engagement feature completion
- Existing System Impact: Builds on existing community, sharing, friend, and feedback surfaces

## Acceptance Criteria

**Functional Requirements:**

1. Community feed backed by the existing `GET /api/sharing/feed` in `backend/src/routes/sharing.ts` (`sharingService.getCommunityFeed`) and the `Share`/`SocialConnection` models
2. Social sharing via `backend/src/routes/sharing.ts` and `backend/src/routes/shareCard.ts`
3. NPS/satisfaction capture via `TournamentFeedback` and community metrics
4. Onboarding and retention metrics surfaced through the existing analytics dashboard

**Integration Requirements:**

5. Feed uses real-time updates from Story 6.4 where appropriate
6. Identity/attribution from Story 6.1; guest interactions remain permitted where safe
7. Existing friend/challenge routes (`routes/friends.ts`, `services/friendService.ts`, `routes/challenges.ts`) remain compatible
8. Metrics feed existing `services/communityService.ts` / analytics

**Quality Requirements:**

9. Feed weekly engagement > 30% of active users
10. NPS collected from > 25% of active users
11. Feed/sharing interactions covered by tests
12. No regression to existing messaging/notification flows

**Non-Functional Requirements:**

13. Privacy controls respected for shared and aggregated data
14. Content moderation/reporting path defined
15. Localization for all new user-facing strings
16. Feed pagination and bounded queries for performance

## Dev Technical Guidance

### Existing System Context

Backend already includes `routes/community.ts`, `routes/sharing.ts`, `routes/shareCard.ts`, `routes/friends.ts`, `routes/challenges.ts`, `routes/messaging.ts`, and services `communityService.ts`, `friendService.ts`, `sharingService.ts`. Prisma models include `Share`, `SocialConnection`, `Friend`, `FriendRequest`, `Challenge`, `TournamentFeedback`, `AnalyticsEvent`. Frontend has social-related screens and i18n (`frontend/Rally/src/i18n`). The gap is a cohesive feed with measured NPS and retention surfaces.

### Integration Approach

Compose the feed from existing share/social/friend data with cursor pagination, add NPS capture to the feedback flow, and surface onboarding/retention metrics via the analytics dashboard. Emit real-time feed events where valuable, and gate private data by the existing privacy middleware (`utils/privacyMiddleware.ts`).

### Technical Constraints

- Respect existing privacy controls and aggregated-only analytics.
- Keep messaging/notification flows untouched.
- Bound feed queries; paginate.

- **Mitigation:** Reuse privacy middleware, aggregate-only analytics, and explicit privacy tests.
- **Rollback:** Disable feed surfacing while keeping data intact.

- [ ] No breaking changes to existing APIs
- [ ] Database changes are additive only
- [ ] UI changes follow existing design patterns
- [ ] Performance impact is negligible
