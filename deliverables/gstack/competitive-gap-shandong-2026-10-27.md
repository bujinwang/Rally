# Rally vs 闪动 FlashX：功能差距与取舍评审

**日期**：2026-10-27
**场景**：竞品调研 + 产品评审（功能差距 / 优先级决策）
**参与成员**：产品官（产品评审员）+ 排障手（调查员）
**评审对象**：微信小程序「闪动 FlashX」对标 Rally 现有能力

---

## 📌 TL;DR（执行摘要）

- **整体结论：🟡 有条件通过** —— 差距清单比预期短得多。闪动 60+ 品类、30 万俱乐部、15 万场馆是「城市级平台」的体量，Rally 不该按它的功能表逐项补齐。
- **真正缺的只有一件事：钱没有流动。** `payments.ts` 存在但**整条路由是注释掉的**，`courtBookings.ts` 同样未挂载；`sessionCosts` 只是计算器（算得出人均，收不到钱）。闪动整个增长飞轮的地基是「报名即付款」，Rally 恰好缺这一块。
- **上线前有 2 个必修缺陷，第一个是功能阻断**：免登录报名页用相对路径 `fetch('./join')` 提交，而分享链接 `/join/{code}` 不带尾斜杠 → 解析成 `/join/join`，**报名按钮点下去大概率 404**。这条不修，谈支付和裂变都没有意义。（建议实跑 30 秒确认。）
- **"约篮球足球" 是个伪需求**：`sportType` 是自由字符串，加两个标签即可，不需要产品设计。
- **明确放弃 5 项**（场馆预订、AI 视频评估、内容动态流、流量入口矩阵、运动保险），理由见第 5 节。

> **一句话概括代码现状**：**卡片能看不能图，页面能开不能报。** 报名、退出、状态轮询三个动作全断在同一个相对路径上（一处可修）；预览图不出是另一个独立问题。断得都很安静——不弹窗、不白屏。

## 1. 各成员核心结论

### 🔍 产品官（产品评审）

- **核心判断**：两家不是同一个物种。闪动是**城市级的组局与场馆交易平台**（供给端 + 流量端 + 交易闭环），Rally 是**球场内的比赛操作系统**（人凑齐之后怎么打）。按闪动的功能表补齐等于放弃自己的立足点。
- **关键建议**：只补「交易闭环」这一段，且用北美可用的形态补（Stripe Connect + 手动捕获预授权），不要照搬微信支付与小程序。把「零账号报名」当资产而不是缺陷——这是闪动做不到的（它必须授权登录）。
- **护城河成立性**：成立。闪动强在「把人凑到一起 + 收钱 + 供给」，Rally 强在「人凑齐之后现场怎么打」，`pairingService`（491 行）+ `aiPairingService`（438 行）是真资产，闪动无对应物。

### 🔧 排障手（代码审计）

- **核心判断**：Rally 的**赛后侧确实扎实**（配对引擎、记分、统计、赛事对阵），但**资金链路与供给链路是空壳**：`payments` 与 `courtBookings` 两条路由在 `routes/index.ts` 里被注释，`courtBookingService.ts:32` 是 `const courtStore: Court[] = []`，`Court/Venue/CourtBooking` 三张表除预测分析里两处读取外零写入。
- **关键建议**：先修 `/join` 的报名提交（相对路径 404）与状态/容量闸，再谈支付——否则收单上线后产生的全是错账。分享域名三处硬编码、两条无路由的 URL 生成路径也需要一并清理。
- **纠正了主理人初判的三处**：① `maxWaitlist` 不是「已实现候补」，字段和配置管道铺好了但**零业务逻辑**，join 路径从不读它；② 满员返回的是 **403 + `SESSION_FULL`**（不是 400/409），`NAME_EXISTS` 才是 409；③ 用户拿到的**不是**完整 RN web bundle，`generateShareMessage` 是零调用方的死代码，真实页面是 `webSession.ts` 的轻量 H5。

## 4. 机制可迁移性：哪些能搬，哪些只能换形态

闪动的机制值得学，但**渠道几乎全不可搬**。这是本次评审最容易被误读的地方。

| 闪动机制 | 能否迁移 | 北美形态 |
|----------|---------|---------|
| 微信群发一条链接接龙 | ✅ 机制可搬 | WhatsApp / iMessage 短链 + 免登录 H5 报名页（**Rally 已有 `/join` 雏形，这是最大资产**） |
| 报名即微信支付 | ⚠️ 机制可搬，渠道不可 | Stripe Checkout / Payment Element，CAD 计价 |
| 鸽子费自动扣违约费 | ⚠️ 需改造 | 报名时 `capture_method: manual` 预授权 hold 定金，爽约后 capture，到场则 cancel（北美不能无授权扣款） |
| 主理人免费 SaaS | ✅ 完全可搬 | 主理人免费 + 按笔收取平台费（Connect `application_fee_amount`） |
| 分账/财务对账 | ✅ 可搬 | Stripe Connect Express，主理人自助 onboarding |
| 场馆智慧管理系统 | ❌ 不做 | 需 BD 逐个签约，重资产，与「零 BD 起步」冲突 |
| AI 视频水平评估 | ❌ 不做 | 需十几万条标注视频，Rally 无数据；现有 skill 自评 + 战绩推导已够用 |
| 微信小程序载体 | ⚠️ 视市场而定 | 若主打加拿大华人社群：微信内 H5 免登录页 > 小程序（小程序无法接 Stripe，支付会死） |
| 抖音/高德/美团入口 | ❌ 不适用 | 北美对应 Google Maps / Meetup，属于后期 BD |

> **关键结论**：Rally 的 `/join/{code}` 免登录报名页，在结构上比闪动更先进（闪动必须微信授权登录）。这不是缺陷，是被埋没的资产——而且它**本来就是服务端渲染的轻量 H5**（`webSession.ts:298` 直接吐 HTML），补闸门、加 OG 标签的成本远低于重做一套报名页。

## 5. 优先级结论

### P0 必做（不做就输）

| # | 功能 | 解决什么 | 实现路径 | 风险 |
|---|------|---------|---------|------|
| 0 | **修通报名链路（P0-0）** | 见下方「真实漏斗」。分享页能打开、能显示人数，但点「报名」后提交打到 `/join/join` → 404。**这条不修，后面全部无意义** | **A（一个函数、三行，修 3 个症状）**：`webSession.ts:678` `./join`、`:634` `./leave`、`:716` `./player-status` 全改绝对路径 `` `/join/${shareCode}/...` ``。**三行必须一起改**——第三行落到 `/join/player-status` 会被 `GET /:shareCode` 当成 `shareCode="player-status"` 走完渲染返回 404 HTML，前端 `.json()` 抛错被 catch 吞掉，表现为**「人数不动」而非报错**，最难排查。**只改 fetch 层，不要改 URL 生成点**——`shareCard.ts:113` 用 `.replace(/\/$/,'')` 主动剥尾斜杠，靠加斜杠绕过等于跟代码库规范对着干。<br>**B（单独排期）**：`shareCard.ts:66` 的 `og:image` 从 SVG 改 PNG（需引入 sharp/resvg 渲染管道） | A 几乎为零，建议配一个冒烟测试；B 工作量与 A 不是一个量级，别混着估 |
| 1 | **报名即付款 + 定金预授权 hold** | 主理人收不到钱，就只能继续用 e-transfer + Excel，产品价值归零；这也是闪动整个飞轮的地基 | 后端：挂载 `payments.ts`，改 Stripe Connect Express + `manual` capture；`sessionCosts` 输出应付额 → 建 payment intent；webhook 驱动 `depositPaid`（替掉手工勾选）。前端：报名页内嵌 Payment Element | 需 Stripe 账号与 Connect 审核；退款/争议流程要一起设计 |
| 2 | **给 `/join` 补闸 + 收敛域名 + 清死链** | 报名页无状态/容量校验，可向已取消活动报名、名额可被撑爆；分享域名三个中最多一个为真 | 四步见下 | 低。但 `/join` 是无鉴权入口，需限流 |

**真实漏斗（经四轮修正后确认）**

Rally 不是「一条入口」，是**两条存活入口**，其中只有裂变那条是坏的：

```
App 内「加入活动」→ mvpSessions API（闸门齐全：SESSION_INACTIVE / SESSION_FULL，均 403）  ✅

路径 A（分享弹窗，4 个按钮都发 /s/{code}）
  /s/{code} 活动卡（9 个 OG 标签，但 og:image 是 SVG → 群里不出图）
    → 点「Join Game」→ /join/{code}  页面正常打开 200，能看到人数
    → 页面内 fetch('./join') → /join/join → 404  ❌

路径 B（详情页/概览页「复制链接」）
  /join/{code}（无 OG）→ 页面内 fetch('./join') → 404  ❌
```

所以准确的说法是：**页面能打开、能显示人数，但报名交不上去**。两条分享路径最终汇到同一个页面，撞同一个坑；App 内加入是正常的。

**为什么「一直没人发现」本身就是信号**

这个洞不隐蔽：URL 就是 `/join/ABC`，看一眼就能推断。但它不弹错、不白屏——页面照常渲染，只是点了报名没反应。**能打开，还坏了这么久，最可能的解释是：分享出去的这个页面，从来没人真的点过「报名」。**

## 6. 护城河：Rally 有、闪动弱的三件事

1. **现场调度引擎**（`pairingService` 491 行 + `aiPairingService` 438 行 + 轮转队列 + 实时记分）

2. **数据资产**（15+ 指标、趋势、对阵图、`PlayerRankingHistory`）
   闪动的数据是「时长/里程/卡路里」这类通用运动记录；Rally 的是**对抗性技术数据**（胜负、搭档组合、局分），可支撑水平分级、配对优化、教练匹配——这是 AI 视频评估的替代路径，且不需要训练视频。**但要注意**：`rankingService.ts:127-135` 的排名更新目前是空壳（无 Elo 计算），这块资产还只是「记录」而不是「洞察」，要补才算数。
3. **零账号报名架构**
   闪动必须微信授权登录才能报名；Rally 的 `/join` 天然免登录。在 WhatsApp 群里传播时，这是转化率上的结构性优势——前提是把它**修通**（现在提交是 404）。

> 产品官判断：**「闪动强在把人凑到一起 + 收钱 + 供给，Rally 强在人凑齐之后现场怎么打」这个判断成立**，且是本次评审最有价值的结论。
